# v0.8.2

本版为用量分析加入分组侧栏，修正 Codex 5h/7d 额度估算串用，并让 Windows 侧升级同时覆盖 WSL 里已安装的 agent。

## 用量分析侧栏

- 新增与磁盘页同款的左侧分组导航，正文独立滚动：
  - 概览：KPI（本周 / 今日 / 缓存 / 速率）+ 套餐配额 + 周窗口 token 统计。
  - 用量趋势：每日 Token（含按小时/周/月粒度）、年度活跃、按天 × 模型、缓存命中率。
  - 项目与模型：模型占比、项目排行。
  - 会话明细：逐会话 token / 项目 / 模型 / 速率表。
- 选中分组持久化到 localStorage；切换分组时退出卡片铺满视图，避免残留展开态。

## Token 单位

- `fmtTokens` 用于 KPI、会话表、图表 tooltip 等，M/B 单位改为固定两位小数。
- 图表坐标轴、图例、项目排行的 `abbrev` 同步改为 M/B 两位小数，避免同一页面出现 1 位/2 位混排；K 仍按整数显示。

## Codex 5h/7d 额度估算

- 根因：估算条目只按 `provider|30 分钟桶` 存储。Codex 的 5h 与 7d 窗口在配额联合重置后会拥有相同的 elapsed（窗口起点相同），两个窗口因此落到同一个条目；后拉取的 7d 估算（含 7d 历史中位）被 5h 行复用，表现为两行显示完全相同的 `已用 / ≈总额`。
- 估算键加入 `window_seconds`（`provider|window|bucket`），查询、±2 桶容差与历史中位全部按窗口隔离。
- 联合重置时两行的“已用 token”相同是真实用量（同一时间起点），但 `≈总额` 各自取本窗口的已用%与历史中位，5h 不会再被 7d 的额度拉高。
- 新增回归测试：窗口隔离、同 elapsed 时总额仍按窗口区分。

## 升级联动 Windows + WSL

- Windows 本地模式下，从配额卡版本徽章启动升级时，会枚举 WSL 发行版并逐个探测该 agent 是否安装；已安装的发行版同步执行对应更新脚本。
- 只更新被点名的 agent；未安装该 agent 的发行版、以及没有 bash 的不可管理发行版自动跳过。
- 升级确认框注明“Windows 与已安装该组件的 WSL 发行版会一并更新”；各发行版各自显示独立的升级日志与进行中状态。

## 验证

- Rust 后端单测通过（含配额归一化与估算历史相关用例）。
- 前端回归测试 8 项通过，Vite 生产构建通过。
- 现场数据核对：Codex 5h 与 7d 的 rolling 用量、历史估算分别落在各自窗口，界面不再共用 7d 中位。
