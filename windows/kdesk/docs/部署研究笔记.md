# 元气桌面免安装部署 —— 研究经验与运维笔记

> 本文记录 2026-08-02 排查与部署过程中确认的事实、踩过的坑和最终方案。
> 脚本实现见项目根目录 `setup_elevated.ps1` 与 `scripts/`。

## 系统组成

| 文件 | 作用 |
| --- | --- |
| `setup_elevated.ps1` | 一次性入口（自动提权）：定位/部署 kdesk → 恢复快照 → 注册集成 → 迁移壁纸缓存 → 创建登录计划任务 → 启动壁纸并运行优化程序 |
| `scripts/deploy.ps1` | 每次登录由计划任务 `KdeskAutoDeploy`（最高权限）触发：停服务/进程 → 恢复 33_1 快照（对抗自动升级）→ 重启服务与壁纸 → 运行优化程序 |
| `scripts/kdesk_locator.ps1` | 多渠道定位 kdesk 安装目录（缓存文件 → 运行中进程 → App Paths → 卸载注册表 → 快捷方式 → 常见目录 → 全盘扫描），始终排除自带备份目录 |
| `scripts/kdesk_integration.ps1` | 共享函数库：便携目录选择、服务/注册表/快捷方式注册、壁纸缓存迁移、壁纸就绪等待、优化程序启动 |
| `kdesk_33_1_backup/` | 33_1 版本完整快照（949 个文件，约 225 MB），主程序、CEF、VC++ 运行库齐全 |
| `wallpaper_cache/` | 壁纸缓存（由脚本从原缓存目录迁移并持续指向这里） |

## 关键结论

### 1. 可以不用官方安装程序，但不能直接在备份目录里运行

- `install.xml` 表明完整功能依赖：`kdeskcore` 系统服务、`HKLM\SOFTWARE\cmcm\kdesk` 注册表项、快捷方式。
- 备份直接运行会污染快照（快照还要用来对抗自动升级），且服务/注册表指向会错乱。
- 方案：把备份复制到独立便携目录再补齐集成。便携目录选择规则——**可用空间最大的非 C 固定盘**（如 `D:\KDesk`），无其他盘时回退 `C:\ProgramData\KDesk`。
- 需要补齐的集成（`Install-KdeskIntegration`）：
  - 服务 `kdeskcore`：`"<target>\kdeskcore.exe" /service cmcore`，自动启动；
  - 注册表：`HKLM\SOFTWARE\cmcm\kdesk`（含 WOW6432Node）的 `ProgramPath`、`Lang=chs`、`setup=1`、`Setup\product_id=1002`；
  - App Paths:`kwallpaper.exe`、`kdesk.exe`;
  - 桌面/开始菜单快捷方式。

### 2. 壁纸缓存路径的真实配置位置

- 不在注册表。真实位置：`%APPDATA%\kdesk\data\wallpaper\interactive.ini` 的 `cachepath`（及 `cachedynamicpath`、`cacheimagepath` 等）。
- 当前壁纸记录 XML/JSON 里也保存了缓存的**绝对路径**，迁移时必须一并文本替换，否则程序仍读旧位置。
- 脚本做法：把缓存固定到 `<项目根>\wallpaper_cache\`，用 robocopy 从旧目录（如 `D:\元气壁纸缓存`）迁移数据，改写 INI 并批量替换配置文件中的旧绝对路径。换电脑后重跑一次入口脚本即可自动重建新路径（每次登录也会重应用，项目挪动后自愈）。

### 3. 恢复快照前必须停 kdeskcore 服务

服务从目标目录运行 `kdeskcore.exe`，不停服务直接 robocopy 覆盖会因文件占用失败。流程：杀进程 → `Stop-Service kdeskcore` → 覆盖 → 重新启动服务。

### 4. 软件性能优化.exe 的行为特征（重要）

- **没有版本信息、启动后不创建任何窗口**、主线程处于 `Wait/UserRequest`（消息循环空闲）,CPU 占用极低，长期驻留不退出。
- 历史日志对照：
  - 在壁纸**未启动**时运行 → 弹报错对话框，人工点掉后以 code=0 退出（7-21 的几次"成功"记录实际如此）;
  - 在壁纸**启动后**运行 → 无窗口静默驻留（疑似给运行中的 kwallpaper 打补丁后常驻守护，属正常工作方式）。
- 因此脚本对它的处理：**等壁纸 UI 真正就绪后启动它，只确认启动成功（15 秒），不等待退出**；重复运行前杀掉上一个残留实例，避免堆积。
- 启动时机的正确等法：等 `kwallpaperui` 进程出现**且** `MainWindowHandle ≠ 0`（实测约 2~3 秒），再追加 10 秒初始化缓冲。只等 `kwallpaper` 主进程是不够的（0 秒就"就绪"，UI 尚未初始化）。

### 5. PowerShell 5.1 脚本必须带 UTF-8 BOM（本次最大的坑）

- 无 BOM 的 .ps1 会被 Windows PowerShell 5.1 按系统 ANSI（中文机器为 GBK）解码，脚本里的中文字面量全部变乱码。
- 实际事故：`软件性能优化.exe` 被解码成 `杞欢鎬ц兘浼樺寲.exe`，日志报 `optimizer not found`。
- 教训：**凡含中文（路径、注释、注册表值）的脚本一律保存为 UTF-8 with BOM**；用编辑器/工具改写后要检查 BOM 是否被剥掉（本次 4 个脚本统一用 `printf '\xEF\xBB\xBF'` 补回）。
- 验证方式：`head -c 3 file.ps1 | od -An -tx1` 应输出 `ef bb bf`。

### 6. 计划任务观察

- 任务 `KdeskAutoDeploy` 由 `schtasks /Create /SC ONLOGON /RL HIGHEST` 创建，`Get-ScheduledTaskInfo.LastRunTime` 为 `1999/11/30` 表示从未触发（用户尚未在任务创建后重新登录过）；手动跑 deploy 不计入。
- 任务操作为交互式（Interactive）+ 最高权限，启动的 GUI 程序会显示在用户桌面。

## 换电脑部署流程

1. 整体拷贝项目文件夹到新机器（位置不限）。
2. 双击运行 `setup_elevated.ps1`（弹 UAC 确认）——找不到已安装的 kdesk 时会自动把备份部署到非 C 盘便携目录并补齐服务/注册表/快捷方式。
3. 首次运行自动迁移壁纸缓存到项目内 `wallpaper_cache\`。
4. 之后每次登录由计划任务自动：恢复 33_1 快照 → 启动壁纸 → 壁纸就绪后运行优化程序。
